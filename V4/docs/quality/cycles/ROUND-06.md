# 第 6 轮：受保护密钥、数据完整性与发布内容

## 目标

关闭开发圣经安全章节中“静态数据加密、密钥保护/轮换、应用启动数据库检查”的核心缺口，且不将尚未迁移的数据源伪装为已加密。

## 实现

| 能力 | 实现 | 约束 |
|---|---|---|
| 数据加密 | `IEncryptionService` + AES-256-GCM，密文包含格式标识、密钥标识、随机 nonce 和认证标签 | 篡改密文会拒绝解密 |
| 密钥保护 | 32 字节随机密钥仅以 Windows DPAPI `CurrentUser` 方式存储在 `encryption-keyring.json` | 不写入源代码、配置 JSON 或日志 |
| 密钥轮换 | 创建新活动密钥；调用方重加密后才能淘汰旧密钥；禁止淘汰当前密钥 | 旧密文在淘汰前可读，淘汰后被安全拒绝 |
| 数据库完整性 | `IDatabase.VerifyIntegrityAsync` 在迁移后运行 SQLite `PRAGMA quick_check` | 无法打开/SQLite 错误返回失败并记日志 |
| 安全评估 | 安全评分纳入应用哈希基线、数据库 `quick_check`、审计链和插件信任状态；应用启动时自动执行 | 未传入数据库的独立单测使用显式可选路径 |
| 审计认证 | 每条审计哈希由 DPAPI 保护的 AES-GCM 密钥封印；旧链会在验证后自动升级 | 不依赖可伪造的裸 SHA-256 链 |
| 发布内容 | Inno Setup 排除 `*.pdb` 与 `*.xml` | 不改变运行时程序集 |

## 未宣称完成的项

- 现有通用设置和 SQLite 业务表尚未迁移为加密存储；它们目前不存储凭据或用户秘密，不能据此声称“全库加密”。
- 审计链已由本机 DPAPI 保护的密钥封印；如攻击者能够以同一 Windows 用户身份调用 DPAPI 或完全控制账户，仍需要外部签名/硬件锚定才能抵御。
- 受信任插件仍安全发现/管理而不执行，隔离插件宿主需要单独进程/权限模型后才能开放。
